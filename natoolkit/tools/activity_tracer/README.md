# Activity Tracer

Activity Tracer is a napari-based application for inspecting time-series imaging
movies, defining regions of interest (ROIs), extracting mean-intensity traces,
and detecting fast events from those traces. It can operate entirely with
manually drawn ROI labels. Suite2p support adds motion correction and automatic
ROI detection but is not required for the basic workflow.

## Design Principles

The application keeps the original movie array separate from the array currently
shown by napari. Temporal cropping, center alignment, and merged views therefore
change the display without discarding the source movie. Per-movie state records
the source array, active time range, alignment references, ROI labels, traces,
colors, and detected events.

Three further choices shape the workflow:

- ROI labels are ordinary two-dimensional integer arrays. They can be drawn in
  napari, imported from `.npy`, exported, copied between movies, or generated by
  Suite2p.
- Trace extraction and normalization are separate. Exported CSV files preserve
  both raw mean intensity and the currently selected normalized value.
- Optional Suite2p processing runs in a napari worker. Long computations do not
  block the viewer, and registered movies are mapped back to their original
  movie layers.

## Launch

Open Activity Tracer from the unified launcher:

```bash
natoolkit
```

or launch it directly:

```bash
activity-tracer
```

The module entry point is also available:

```bash
python -m natoolkit.tools.activity_tracer.gui
```

napari can additionally discover `ActivityTracer` from the `natoolkit` plugin
manifest.

Install the optional Suite2p integration with:

```bash
pip install -e ".[suite2p]"
```

## Recommended Workflow

```text
Import one or more movies
  -> optionally select spatial and temporal ranges
  -> optionally run Suite2p motion correction
  -> draw, load, copy, or detect ROI labels
  -> extract one trace per ROI and movie
  -> choose a normalization
  -> optionally detect FRAME-style events
  -> export ROI labels, activity traces, and events
```

## Movie Import and State

Use **Import Movie** to select one or more files. `.npy` arrays are opened with
NumPy memory mapping. Other formats are passed to napari's reader system. Each
movie must behave as a three-dimensional array with axes `(time, y, x)` for the
full analysis workflow and for Suite2p.

The selected napari image layer is the active movie. The information panel shows
its source shape, displayed shape, data type, and current alignment references.
Removing an image layer also removes its in-memory Activity Tracer state.

### TimeROI

`Start` is inclusive and `Stop` is exclusive. **Use Full Range** restores
`[0, frame_count)`. A TimeROI changes which frames are displayed and analyzed:

```text
displayed movie = source movie[Start:Stop]
```

Negative starts or stops beyond the source length may be produced by temporal
alignment. Missing frames are represented by zero padding. Changing a TimeROI
invalidates temporal-reference metadata and recomputes an existing trace when
possible.

### Center Alignment

**Set Spatial Center Ref** stores the selected movie's `(y, x)` shape.
**Spatially Align** center-crops larger selected movies and symmetrically
zero-pads smaller selected movies to that shape. This is shape alignment, not
feature-based image registration.

**Set Temporal Center Ref** stores the selected movie's displayed frame count.
**Temporally Align** assigns every selected movie a centered interval of the
same length. Longer inputs are center-cropped; shorter inputs are padded with
zeros. Select the target movie layers in napari before applying either alignment.

## Suite2p Integration

Motion correction and automatic ROI detection are available only when the
`suite2p` optional dependency is installed.

### Motion Correction

**Motion Correction** concatenates the imported movies into one Suite2p
registration session while preserving a frame range for each input movie. The
adapter:

1. validates that every movie has shape `(time, y, x)`, a common spatial shape,
   and at least 10 frames in total;
2. writes batched `int16` input frames to `suite2p/plane0/data.bin`;
3. runs rigid or non-rigid Suite2p registration on the selected CPU, CUDA, or
   MPS device;
4. maps each registered frame range back to its original napari layer;
5. keeps the pre-registration source so **Discard motion correction** can
   restore it.

The settings dialog exposes the device, non-rigid registration, initialization
frame count, batch size, rigid shift limit, smoothing, block size, non-rigid
shift limit, and bidirectional phase correction. Reusing a non-empty Suite2p
output directory requires explicit replacement confirmation.

### ROI Detection

ROI detection requires a completed motion-correction session that still matches
the currently imported movies. It runs Suite2p detection on the registered
binary using the selected sampling rate, calcium decay time, algorithm,
diameter, threshold scaling, maximum ROI count, spatial scale, overlap limit,
bin count, and denoising option.

Suite2p `stat.npy` pixel coordinates are converted into a label image. Accepted
ROIs receive positive integer IDs. Detection can create one shared ROI map for
the registered session or separate maps for individual movies, depending on the
selected operation and ROI mode.

### Merged View

Merged view is available after motion correction. It lazily concatenates each
movie's current TimeROI, in the current bottom-to-top napari layer order, into a
Dask-backed image named `Merged registered movies`. Separate layers are
temporarily removed from the viewer but their state is retained.

Trace extraction in merged view still produces per-source-movie export rows. The
displayed plot concatenates only ROI IDs that are present in every contributing
movie. Disable merged view to restore the original layers.

## ROI Workflow

An ROI label image has the same `(y, x)` shape as its target movie. Background is
zero and every ROI is a positive integer. Overlapping polygons with the same
label replace that label's previous pixels, so one ROI ID represents one region.

### Shared and Unique Modes

- **Shared** keeps one ROI label map for all movies. Use it when the movies are
  already spatially registered and the same cells should be traced everywhere.
- **Unique** keeps an independent ROI map in each movie's state. A movie can be
  set as the ROI reference and copied to another movie when their spatial shapes
  match.

**Initialize Unique ROIs from Shared** copies the current shared map into the
per-movie states. Later edits are independent.

### Manual Editing

Enable **Show ROI layer**, select napari's polygon tool, and draw the active
label. The application binds these keys to the ROI layer:

```text
T  submit the current non-empty ROI and advance to the next label
C  clear the currently selected ROI
```

The ROI Manager lists submitted IDs, selects an ROI for editing, and displays
the same cyclic colors used by the label layer. The companion points layer shows
the ROI number near a representative central pixel. An enhanced mean image is
shown behind the labels to make boundaries easier to identify.

### Import and Export

**Load ROI Labels** accepts a two-dimensional `.npy` array whose shape matches
the target movie. Every positive value is treated as an existing ROI ID.
**Export ROI Labels** writes the current integer label array to `.npy`.

Changing, loading, or copying ROI labels clears traces and events affected by
that label map; extract the activities again afterward.

## Activity Extraction

For each ROI ID `r` and displayed frame `t`, the raw activity is the arithmetic
mean of all movie pixels carrying that label:

```text
trace_r[t] = mean(movie[t, labels == r])
```

Shared mode applies the common labels to each movie. Unique mode uses the label
map stored for that movie. The labels must match the displayed `(y, x)` shape,
and the TimeROI must be non-empty.

Use **Show All Traces**, **Hide All Traces**, or individual ROI checkboxes to
control the plot. Visibility and trace color affect visualization only; exported
activity data includes every extracted ROI.

## Normalization Methods

Normalization is computed from each complete extracted trace.

- **Raw** returns the mean-intensity trace unchanged.
- **dF/F0** sets `F0` to the selected percentile of the trace and computes
  `(trace - F0) / F0`. The default percentile is 10.
- **SNR(dF/F0)** first computes dF/F0, subtracts its median, estimates noise as
  `1.4826 * median(abs(signal - median))`, and divides by that noise estimate.
- **FRAME_SNR** applies the FRAME-style processing described below.
- **Z-score** computes `(trace - mean) / standard_deviation`.
- **Min-max** computes `(trace - minimum) / (maximum - minimum)`.

Constant or otherwise zero-denominator traces return zeros. Selecting
**Negative-going signal** reverses the sign for dF/F0, SNR(dF/F0), and
FRAME_SNR so valleys are treated as positive events.

## FRAME-Style Event Detection

The event detector operates on one extracted trace at a time:

1. convert the median baseline duration from milliseconds to frames and apply a
   nearest-edge median filter;
2. subtract the baseline from the raw trace;
3. apply a fifth-order low-pass Butterworth filter;
4. reverse the sign when negative-going signals are selected;
5. estimate noise as the standard deviation after a fifth-order high-pass
   Butterworth filter;
6. divide the spike-oriented trace by that noise to obtain `FRAME_SNR`;
7. call `scipy.signal.find_peaks` with the SNR threshold and the minimum
   inter-spike interval converted to frames.

The default controls are 1000 Hz sampling, a 500 ms median baseline, 250 Hz
low-pass, 20 Hz high-pass, 3 ms minimum interval, and SNR threshold 4. Both
filter cutoffs must be below Nyquist.

## Output Files

### Activity CSV

**Export Activities** writes:

| Column | Meaning |
| --- | --- |
| `movie` | Source movie layer name. |
| `roi` | Positive ROI ID. |
| `frame` | Zero-based offset inside the current TimeROI. |
| `source_frame` | `TimeROI Start + frame`. |
| `mean_intensity` | Raw ROI mean for that frame. |
| `normalization` | Human-readable normalization and settings. |
| `normalized` | Normalized value for that frame. |

The `movie` and `source_frame` columns are consumed by Activity–Sleep State
Aligner.

### Event CSV

**Export Spikes** writes:

| Column | Meaning |
| --- | --- |
| `movie`, `roi` | Trace identity. |
| `frame` | Event frame inside the TimeROI. |
| `source_frame` | Event frame in the original source movie. |
| `time_ms` | Time relative to the TimeROI at the configured FPS. |
| `source_time_ms` | Time relative to source frame 0. |
| `peak` | Filtered spike-oriented amplitude. |
| `noise` | High-pass noise standard deviation. |
| `snr` | Peak FRAME_SNR. |

## Important Limitations

- Center alignment does not estimate spatial translations or biological
  correspondence. Use motion registration before sharing ROIs across movies.
- Zero padding contributes zero-valued frames to traces. Exclude padded regions
  when they should not be analyzed.
- ROI trace extraction is an unweighted pixel mean and does not perform neuropil
  subtraction.
- Normalization and event detection are descriptive signal-processing steps;
  they do not establish that an event is a biological action potential.
- Suite2p output replacement can remove a previous `suite2p` result directory;
  the GUI requests confirmation before doing so.
